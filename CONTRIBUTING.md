# Contributing to Readmarks

Fork it, open an issue, or send a pull request.

## What helps most

1. **Attacks.** A way to game a figure or forge evidence, with a test that shows it. This is how the specification got to its second draft.
2. **Compatibility reports.** What a real assistant does with the link binding: does it follow the three steps, what does its signature cover, can its share pages be fetched.
3. **Independent implementations**, in any language, checked against `verify/readmarks-verify.py`.
4. **Witnesses.** The log uses C2SP checkpoints so that independent parties can cosign them.
5. **Origin registry updates**, each citing the operator's own page.

## Rules

- A change to the specification comes with the attack, test or measurement that motivates it.
- Nothing that asks an agent to leave a mark. Section 10.1 is not negotiable.
- Forks keep the credit ("based on Readmarks, started by SGAI Studio Pte. Ltd., UEN 202620727K") and say what they changed.

SGAI Studio Pte. Ltd. stewards versions 1.x. If you disagree with a decision, fork: the licences exist for that.
